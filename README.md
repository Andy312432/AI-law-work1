# LexiArbiter：術語、解釋與概念標註

這是一個離線的 Python / PySide6 桌面標註工具。依據「標註 GUI 程式說明」第 11–12、56–57 頁，以及測試資料的標註任務單，這次要完成的工作是：**把每一個術語出現的位置，連結到原文中的解釋範圍、對應概念與上位概念，並存成 `.lexa`。**

PDF 前面的環境設定與 GUI 教學是背景說明；作業的驗收目標在第 56–57 頁。程式不需要呼叫 AI、做法律推論或自動生成解釋。

## 必要功能與實作

| 功能 | 程式行為 |
| --- | --- |
| 開啟資料 | 支援原有 `.docx`、判決 `.json`、`.lexa` 與模型 `.txt`；保留原文作為標註座標基準。 |
| 標註術語 | 選取文字後按「專業術語」或 `1`。每一筆都有獨立範圍與 ID。 |
| 概念與上位概念 | 同一個對話框可選既有概念或輸入新名稱；名稱相同會重用概念 ID。 |
| 標註解釋 | 先點術語，再選取解釋文字，按「設定解釋」或 `Ctrl+L`；修改的是該筆術語的 `explanation_start/end`，不另建一條解釋標籤。 |
| 沒有解釋／最上層 | 解釋預設填術語本身；上位概念預設選「同本概念，最上層」，兩者均有實際值。 |
| 自動標註相同術語 | 預設開啟。建立術語後，將全文可用的相同字串建立成正式標註，會一起存進 `.lexa`。 |
| 重疊處理 | 同群組的術語範圍不可重疊；手動新增可確認後取代舊標註。自動新增保留既有標註並略過重疊。解釋範圍可互相重疊，也可包含其他術語。 |
| 概念關係樹 | 右側以「上位概念 → 概念 → 術語實體」呈現關係，可搜尋、展開、收合及放大檢視。點概念查看相關術語，點術語跳回原文，雙擊可修改這一筆的概念與上位概念。 |
| 查看與導覽 | 點選術語顯示解釋的藍色高亮；滑鼠停留顯示資訊；右側可切換標註，點概念節點可循環跳到該概念的術語。 |
| 儲存與恢復 | `Ctrl+S` 儲存 `.lexa`，可再開啟繼續修改；保留 60 秒自動備份及當機備份。正式存檔先檢查必填欄位，再以暫存檔取代原檔。 |

`Annotation` 與 `Document` 的資料欄位維持原樣；只修正 `Document.annotations_in_range_for_group()` 未完成的重疊判斷。保留原本自訂的「原因」標籤，快捷鍵改為 `2`，避免與「專業術語」的 `1` 衝突。該標籤不等於「設定解釋」。

## 啟動

需要 Python 3.10 以上。Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

這個 repo 已有 `.venv` 且安裝好套件時，只需執行最後一行。也可雙擊 `啟動程式.bat`，它會使用 repo 內的虛擬環境。

## 一筆標註怎麼做

1. 開啟 `test_example.docx`。
2. 選取「債之發生原因」，按「專業術語」或 `1`。
3. 概念輸入「債之發生原因」；上位概念維持「同本概念，最上層」，按確定。
4. 這筆成為右側目前術語。選取從「大致區分」到「自由」。的解釋文字，按 `Ctrl+L`。
5. 右側會顯示術語範圍、概念、上位概念及解釋範圍。按 `Ctrl+S` 另存 `.lexa`。

要更換既有術語的解釋，先點該術語或從右側下拉清單選取，再重新選取解釋。選取解釋時，即使跨過別的術語，也仍會更新原本選定的那一筆。若沒有解釋，按右側「解釋用術語本身」。

所有範圍都採原文的 Python 字元座標 `[start, end)`：包含起點、不包含終點。編輯器會處理 CRLF、隱藏的 `<br>` 與 emoji 的 UTF-16 座標轉換。

## 互動概念關係樹

開啟文件後，右側的「概念關係樹」會依實際標註建立階層。例如測試資料顯示：

```text
債之發生原因
├─ 意定之債
│  ├─ 「意定之債」[55, 59)    ← 文中的一筆實體
│  └─ 「意定之債」[65, 69)
└─ 法定之債
   ├─ 不當得利
   ├─ 侵權行為
   └─ 無因管理
      ├─ 「無因管理」[105, 109)
      └─ 「無因管理」[121, 125)
```

操作方式：

- 點節點左側箭頭展開／收合，或按「全部展開」「全部收合」。
- 輸入概念名稱或術語搜尋，符合項目與其上層路徑會保留；清除搜尋會恢復原本的展開狀態。
- 點概念節點，循環跳到該概念的術語，並高亮相關文字。
- 點「術語實體」列，直接跳到原文的那個位置，在下方查看概念、上位概念和解釋。
- 雙擊術語列、按 `F2`，或在右鍵選單按「修改這一筆的概念／上位概念…」，即可修改該筆關係。確認後樹會更新，`Ctrl+S` 儲存到 `.lexa`。
- 按「放大檢視」開啟獨立、可調整大小的視窗；原文跳轉與修改功能相同。
- 點原文中的術語時，樹上也會選到對應項目。
- 資料夾檔案清單移到旁邊的「資料夾檔案」分頁；按工具列「開啟資料夾」會自動切到該分頁。

同一概念在不同標註中若有不同上位概念，會分別出現在各上位概念下，每個分支只列出屬於該關係的術語位置。修改一筆不會更改其他筆的上位概念。最上層概念「上位填自己」會呈現為根節點；真正的循環關係會標示「循環連結」並停止重複展開。樹狀圖沿用既有 `.lexa` 欄位，不額外建立另一份關係資料。

## 自動標註的明確規則

- 比對原文的完全相同字串，區分大小寫，不做斷詞、同義詞擴充或 AI 推測。
- 每個新位置共用來源的 `concept_id` 與 `broader_concept_id`。
- 每個新位置的解釋先用**該位置自己的術語範圍**，避免把其他段落的解釋誤套到這裡。可逐筆改成當地的解釋。
- 既有標註的概念與解釋均保留；重複操作不會新增相同範圍的標註。
- 例如先有「損害賠償責任」，之後自動標「損害賠償」時，會略過前者內部的四字範圍。反過來也一樣保留既有標註；若要改用較長範圍，請手動選取並確認取代。
- 相同字串本身互相重疊時，先保留使用者選的位置，再由左至右加入其餘可用範圍。
- 狀態列顯示自動新增與略過重疊的數量。工具列的「自動標註相同術語」可隨時開關；開關影響之後的標註操作，既有標註會保留。

`auto_annotate_matches` 儲存在 `configs/user_preferences.json` 的 `behavior` 裡，預設為 `true`。`auto_popup_on_selection` 控制拖選後的快速選單。術語模式仍須填寫概念與上位概念，因此建立／修改時會開啟概念對話框。

## 驗收與測試

`tests/fixtures/` 保存使用者提供的原始 DOCX 與參考 LEXA，原始 Downloads 檔案不會被修改。執行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

測試涵蓋：

- DOCX 原文與參考 `.lexa` 的 1,209 字完全一致。
- 依任務單完成 11 筆標註，經 GUI 儲存並重讀，比對術語範圍、解釋範圍及概念名稱。
- 真實 Qt 對話框、快捷鍵 `1`、解釋按鈕、術語點擊與概念點擊。
- 概念階層、11 筆術語位置、多個上位概念、循環與缺漏資料的顯示、搜尋、選取同步、放大視窗，以及從樹上雙擊修改關係後儲存並重讀。
- 自動新增、重複操作、長短術語重疊、取消操作、Unicode 座標。
- 必填欄位檢查、存檔失敗保留原檔、既有模型匯出的概念隔離。

**重現任務單的 11 筆時，先關閉「自動標註相同術語」。** 參考檔只有指定的 11 個位置；開啟新增功能後，全文其他相同術語也會成為標註，因此總筆數會增加。

比對時忽略隨機的標註 ID 與概念 ID，改比對概念 ID 指向的名稱。來源檔名也會反映實際載入的 DOCX 名稱。`.txt` 是既有模型用的輸出格式，不包含完整解釋關聯；要保留作業要求的全部資訊，請儲存 `.lexa`。

## 主要程式位置

- `lexiarbiter/core/annotations.py`：建立術語、共用概念、自動標註與必填檢查。
- `lexiarbiter/app.py`：視窗操作、對話框、解釋設定、存檔與導覽。
- `lexiarbiter/widgets/editor.py`：原文座標映射、點擊訊號、提示及高亮。
- `lexiarbiter/widgets/concept_panel.py`：概念對話框與標註詳情。
- `lexiarbiter/widgets/concept_tree.py`：互動概念關係樹、搜尋、原文連動與放大視窗。
- `lexiarbiter/core/io.py`：沿用 DOCX 解析、LEXA 讀寫與模型匯出。
